Одностраничное веб-приложение на Next.js + Tailwind, адаптированное и под desktop, и под mobile.

Это будет демо RAG для заказчиков, где человек без технического бэкграунда может за 1 экран понять сценарий:

загрузил файл
дождался успешной обработки
задал вопрос
получил ответ от ИИ по файлу
Что будет на странице
Основной сценарий

Один, максимально простой:

загрузка одного файла
допустимые типы:
PDF
DOC/DOCX
TXT
после загрузки показываем:
статус загрузки
статус успешной обработки
после этого доступен блок вопросов
Вопрос-ответ
поле ввода вопроса
готовые кнопки с demo-вопросами
ответ от ИИ должен показывать:
сам ответ
цитаты / источники
confidence / уверенность ответа
историю диалога не храним
превью файла не нужно
Источники данных
1. Mock mode
встроенный mock handler
можно показывать демо без реального сервера
ответ от ИИ идёт стримингом, чтобы текст появлялся плавно по буквам
2. Real server mode
подключение к реальному backend через API из swagger YAML
переключение между mock и real — видимый тумблер для пользователя
если выбран real server, но backend недоступен:
явно показываем сообщение, что сервер пока не запущен
Ошибки

Нужны разные состояния:

сервер недоступен
неподдерживаемый файл
ошибка загрузки
ошибка обработки
пустой ответ
таймаут / общая серверная ошибка

UX-логика, которую я предлагаю

Чтобы заказчик сразу понял, что такое RAG, а экран был минималистичным, я предлагаю такую структуру страницы:

Верхний блок

Короткий премиальный hero:

заголовок в духе
“Задавайте вопросы по своим документам”
подзаголовок
“Загрузите файл и получите точный ответ с источниками за секунды”

Справа или сверху в компактной зоне:

тумблер Mock / Live server
индикатор статуса сервера
переключатель темы
Центральный блок

Две основные карточки:

1. Upload card
drag & drop
кнопка выбора файла
список допустимых форматов
после загрузки:
имя файла
статус “обработан”
иконка успеха
2. Ask card
поле вопроса
demo-кнопки с готовыми вопросами
кнопка “Спросить”
во время ответа:
streaming text
skeleton / typing state
Блок результата

После ответа показываем:

основной ответ
confidence badge
источники / цитаты в отдельных компактных карточках
Готовые demo-вопросы, которые я бы заложил

Универсальные, понятные для заказчика:

О чём этот документ?
Какие ключевые выводы здесь есть?
Найди важные ограничения или условия
Какие действия или рекомендации описаны в документе?

Если в swagger потом будет видно, что у вас доменно-специфичный кейс, можно поменять.
